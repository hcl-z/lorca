一句话

文件是唯一的真相，索引只是加速器

◈
选型：文件 + FTS5 + 梦境整理 + 纠正沉淀为 skill

向 OpenClaw 借“无向量 FTS5”的可审计明文，向 Letta 借 sleep-time 的整理节拍，向 Graphiti 借 valid_from / valid_to 的有效期，向 Mem0 借“写入前先比对”。画像类当轮即写并同步到所有设备，普通记忆靠“被复用”来晋升。开发期在桌面里默认开启一块极简追踪面板。

读取

每轮按需召回

保留 200 行 / 24KB 常驻；其余按当前用户消息做 FTS5 top-k，拼在 transcript 之后，不污染系统提示缓存。

整理

每晚梦境

按 复用次数 × 查询多样性 × 时近度 打分；矛盾自动 supersede；久未复用的归档。

学习

从纠正里学做法

同一类 edited / rejected 出现 2 次即提议 skill 或画像规则，走现有 feedback.propose 审阅。

问题

为什么以前总不更新

根因 1 · 存错地方

画像跟着机器，不跟着人

PROFILE.md 在 Runner 本地（~/.lorca/memory/profile/），MEMORY.md 跟着单个 bot。你以为教的是“你”，实际教的是“这台机器上的这个 bot”。

  • Mac 上教的，手机上不认识
  • A bot 学会的，B bot 要重学
根因 2 · 存得太慢

要等很久才学一次

capture 要等 静止 5 分钟或攒够 8 条才触发；一次最多 8 条且不超过存量 25%；flush 只在压缩前跑。

  • 短对话永远轮不到
  • 新 bot 第一次只学 1 条
根因 3 · 旧的不让位

只会追加，不会取代

“住上海”和“住杭州”并存，下次召回随机命中一条，看起来就是没学会。缺少按主题（slot）的 supersede。

  • 偏好改了，旧的仍生效
  • 召回变得不稳定
→
三个根因 → 三条修复（都在本方案里）

存错地方 → 画像做成账号级加密 blob同步；存得太慢 → 画像走快速通道当轮即写；旧的不让位 → 同 slot 自动取代并关闭旧条目有效期。

怎么做 · 召回

不靠向量，靠“被复用”来排序

索引长什么样

-- rusqlite 0.37 bundled 已在 Cargo.toml
CREATE VIRTUAL TABLE memory_fts USING fts5(
  doc_id, scope, kind, title, body,
  tokenize='unicode61 "remove_diacritics 2"'
);
CREATE TABLE recall_log(query, doc_id, at, rank, injected);
CREATE TABLE doc_meta(doc_id PRIMARY KEY, valid_from, valid_to, pinned, source);

中文分词无需模型：Rust 侧用 jieba-rs 离线分词后写入 FTS5，纯本地、可离线、可审计。

每轮怎么选 6 条

先取 BM25 top-20（<5ms），再按六信号重排取 6 条注入，约 400 token：

score = 0.40*BM25 + 0.24*log(1+复用次数)
      + 0.15*查询多样性 + 0.15*时近度(14天半衰)
      + 0.10*巩固度
-- 另：pinned +0.20，推断 -0.15，过期排除
-- 晋升门槛：复用≥3 且 跨≥2 个不同问题

把本该给语义分的权重，挪给了“在多少个不同问题里被用过”——越通用的越该常驻。

◎
那 paraphrase 怎么办？

靠行为而非语义：一条笔记若在“周报、纪要、飞书排版”三个不同查询里都被用过，它自然会晋升，无需向量算余弦。兜底：让当轮模型顺手给 20 条打 1–5 分，复用一次本来就要付的调用，不新增模型。

怎么做 · 画像

让个人信息必更新：当轮即写

USER.md 长这样

## 基本信息
- 2026-10-24 · 住杭州 <!-- id:7f3a slot:city -->
## 偏好
- 2026-10-24 · 偏好短回复 <!-- id:21c0 slot:tone -->
## 推断区
- [推断·3/5] 可能常在飞书协作 <!-- id:9a01 -->

每条带稳定 id 与 slot。推断区单独放、可一键驳回，不与“你说的”混在一起。

当你说“我搬杭州了”

抽成 {slot:city, 值:杭州, 引文:原话}
→ 过同一道门禁（引文·注入·脱敏）
→ 同 slot 自动取代：旧“上海”加删除线，valid_to=今天
→ 写 USER.md → 同步到所有 Runner → 下一轮所有 bot 生效

画像类不等 5 分钟、不受 8条/25% 限制；普通事实仍走“短期笔记 → 梦境晋升”。

矛盾 = 取代

同 slot 新值到，旧条目关闭有效期，不进永久遗忘，问“以前住哪”仍可答。

同步 = 账号 blob

复用 credentials 的机制，按 slot 以 (id,时间) 合并。

可见 = 可撤销

DM 里轻量确认“已更新：住杭州（原上海）· 撤销”；设置页“关于你”即 USER.md，直改实时同步。

开发期

只在桌面、默认开启的极简追踪

回答三问：刚才召回了什么、写入是否成功、旧的是否被取代。不堆事件，只留三种人话。

召回了什么

recalled — 针对这句用户消息，命中哪几条、注入了哪几条。点开看 BM25 与标题。

写入是否成功

saved — 写进 MEMORY / USER 的是哪条；被门禁拦住的也在此显示原因（一行话）。

被取代了什么

superseded — 同 slot 旧值 → 新值，旧条目加删除线并关闭有效期。

落地

五个 PR，每个可单独合入

  1. P1 · 索引与召回 — memory_index.rs（FTS5）覆盖记忆与聊天记录；recall 改走索引；context_notes 注入 top-k。已搭骨架，本分支即 P1。
  2. P2 · 画像快速通道 — 画像 slot 当轮直写、自动取代、同步到所有 Runner。
  3. P3 · 梦境整理 — memory_dream.rs 每晚按复用打分晋升/归档，写 DREAMS.md 可撤销。
  4. P4 · 纠正沉淀为 skill — 聚类 feedback 的重复纠正，≥2 次提议 USER 规则或 skill。
  5. P5 · 桌面追踪面板 — sheet_trace.go + memory_trace.rs 接线；默认开启，可并行于 P2–P4。

怎么算“越用越懂”

重复交代率（“我说过了”）· 纠正率（draft 被编辑/否决）· 召回精度（命中被复用占比）· 记忆成本（每轮 note 的 token 数）。

回放集

偏好、矛盾、过期、注入各若干段对话，每个 PR 都跑一遍；题型参照 LongMemEval。

边界

不做的事

不做向量

几千条量级的个人记忆，FTS5 + 复用信号已足够；向量带来的下载与常驻不符合单二进制与离线约束。

不做图库

时序用 valid_from/valid_to 轻量表达；不引入 Neo4j / FalkorDB。

不让推断污染画像

inferred 只能进推断区，需复用或确认才转正；tool/web 来源在梦境前剔除。

不改信任模型

画像同步复用账号 DEK 与签名；relay 仍只见密文。
