# Skills

A skill is a folder with a `SKILL.md`, in the agentskills.io format Claude Code, Codex, and Cursor read: frontmatter with a `name` (the folder's name, a lowercase slug of at most 64) and a `description` (what it does and when to use it), the instructions after it, and any files beside it, conventionally `references/`, `scripts/`, and `assets/`. Saving a skill writes its folder; the bots use it from their next turn. There are no drafts and no revision history. `crates/cli/src/skills.rs` owns the folders; the apps read and edit them through the CLI. Plugin-provided skills stay in their plugin's folder ([Plugins](plugins.md#plugins)).

## Folders and scopes

A Runner keeps skills in three places under the CLI's home (`~/.lorca`, `~/.lorca-dev`, or `LORCA_HOME`):

| Scope | Folder | Who uses it |
| --- | --- | --- |
| `shared` | `<home>/skills/<name>/` | Every bot on the Runner |
| `bot` | `<home>/workspaces/<bot id>/skills/<name>/` | That bot, in every chat; beside its memory |
| `project` | `<home>/groups/<chat id>/skills/<name>/` | The bots in that group, in that group |

A turn sees the shared skills, its bot's, and, in a group the bot is in, the group's (`scopes_for_turn`). A name in more than one of them resolves to the bot's, then the group's, then the shared one (`skills::find`), which is how a browser replay picks a skill's recorded steps.

A name is checked as a slug and refused when it is a Windows device name; a path inside a folder has no `..`, no leading `/`, no backslash, and no `.git`, `.trash`, or `.lorca-` part. Ids of bots and groups never carry a separator. A save builds the folder beside the old one (`.tmp-…`), moves the old one into the scope's `.trash/<unix seconds>-<name>/`, and renames the new one into place, so a bot never reads half a skill and Windows, which cannot rename over a folder, works the same. A removal moves the folder into the trash too. What has sat in a trash for 30 days is deleted when the CLI starts. Folders that start with a dot are never skills.

## The skills Lorca ships

`crates/cli/src/docs.rs` holds four skills, their files embedded from `crates/cli/skills/`, and writes them into the shared folder as the CLI starts, each with a `.lorca-builtin` mark holding a hash of what this build ships. A copy whose mark differs is rewritten; a folder of that name without a mark, one the user made or took over by removing the mark, is left alone. The apps list them, cannot edit or remove them, and no shared skill of the user's can take their names.

- `lorca` points the bot at Lorca's user docs on the website ([Website](website.md)): `https://lorca.app/llms.txt`, the pages as `/docs/<page>.md`, `/llms-full.txt`, and the Chinese ones under `/zh`, fetched with the web fetch tool or `curl`, never from memory or Lorca's binary.
- `write-skill` says how to keep a way of working as a skill: which folder, the format and its limits from the spec, short instructions with detail in `references/`, relative paths, no secrets, scripts that pass Auto-review, a try with a real request, and its `references/format.md` holds a template and a checklist.
- `save-skill` brings in skills other tools saved: it lists only the folders in its `references/locations.md` (`~/.agents/skills`, `~/.claude/skills`, `~/.cursor/skills`, and the rest from the skills CLI's list of agents, plus a project's `.agents/skills`, `.claude/skills`, and `skills`), never the home folder recursively, counts a skill once through `realpath`, asks the user with `ask_user` which to bring in, where, and whether to move and link, move, or copy, then does it with `mv`, `cp -R`, and `ln -s`, which pass Auto-review outside Lorca's folders. It runs none of their scripts.
- `ego-browser` is ego (lite)'s own skill for its browser, with its files and MIT license as ego publishes them: the `ego-browser nodejs` scripts, the API in `references/`, how to install ego, and notes on a few sites. A turn lists it only when ego is the [browser](browser.md) the bot uses.

## In a turn

Every turn's system prompt names the three folders and lists the skills it sees in agentskills.io's `<available_skills>` shape (`lorca_agent::harness::format_skills_for_system_prompt`): each skill's name, description (cut to 300 characters), and its `SKILL.md`'s absolute path, the bot's first, then the group's, then the shared ones, within 6,000 bytes, then how many more the folders hold. The bot reads a skill with `read` when one fits and resolves its relative paths against the skill's folder. It writes one with `write` and `edit`, and the write-skill skill says how; nothing else stands between a write and the next turn's prompt.

`read`, `grep`, `find`, and `ls` on a path inside one of the bot's skills folders run for a bot whose Access turns file reading off (`permissions::check_tool_call`), so every bot can read its skills. A skill's text grants no permissions. A command that names a path in a skills folder, or runs from one, is never in [Auto-review's](auto-review.md#fast-paths) Lorca-folders fast path: a skill's scripts may be a community's code. A bot that copies a script elsewhere first is reviewed as any command there.

When a turn ends, the CLI compares the turn's skills folders with what they held before it (`skills_turn::fingerprint`, by each folder's file count, sizes, and newest change) and says in the chat which skills the bot saved, changed, or removed, with their paths, at most five lines.

## Sync

A bot's and a group's skills travel to the account's other Devices (`crates/cli/src/skills_sync.rs`): each folder as a zip, file permissions kept, in a blob of its own encrypted with the account DEK, in a latest-only slot named for the scope and the skill, in the group of the scope's chat (the group's own, or the bot's DM), so deleting the chat deletes it on the relay. The blob keeps the kind name `playbook`, and its body says `v: 2`. A removed skill travels as a note that it is gone. The Runner that runs the bot, or a member of the group, sends a skill after a save through the CLI, after each turn (since a bot writes its skills as files), and at start; every Device with a CLI keeps what arrives, so a bot that moves to another Runner finds its skills there and a Runner that is set up again gets them back. The copy that changed last wins, and the one it replaces goes to that scope's trash. A folder whose zip passes 8 MiB stays on its Runner. A rotated account key sends them all again. Shared skills and the ones Lorca ships stay on their Runner.

A CLI that finds the older encrypted library, `playbooks.enc`, writes the newest saved revision of each skill it holds for its bots and groups as folders (examples become a section of the instructions), drops drafts and removed skills, and renames the file `playbooks.enc.migrated`.

## Importing from a community

`crates/cli/src/skill_hub.rs` searches skills.sh and fetches a skill from a public community into a scope's folder. `skills.search` asks skills.sh's public search as its own search page does (`/api/search?q=…&limit=100`; a smaller limit ranks differently), which takes a query of two characters or more and answers in under a second, and lists its skills in GitHub repositories as `owner/repo@skill` in skills.sh's order, with the repository, the install count, and whether skills.sh marks it a copy of another repository's skill; one published by a website rather than a repository, which the import cannot read, is left out, and a shorter query lists nothing. `LORCA_SKILLS_SH_URL` points the search at a mirror. A source to import is a ClawHub skill (`clawhub:<publisher>/<slug>`, or its page on clawhub.ai or hub.openclaw.ai), a skills.sh page, or GitHub: `owner/repo`, `owner/repo/path`, `owner/repo@skill`, or a github.com link to a repository, a folder, or a `SKILL.md`. ClawHub serves a skill as an archive (`/api/v1/download` by slug and `ownerHandle`, since several publishers can use one slug and a bare slug answers 409; one it keeps on GitHub is answered with the repository and commit, and read from there). From GitHub the CLI lists the repository's tree once (`/repos/{owner}/{repo}/git/trees/{ref}?recursive=1`, with `GITHUB_TOKEN` or `GH_TOKEN` when one is set, sent to GitHub's API alone), picks the skill's folder in it, and downloads that folder's files from raw.githubusercontent.com, eight at a time, links and submodules left out; a skill of more than 500 files or 128 MiB is refused. When GitHub does not list the tree (its hourly limit, a truncated tree, a mirror without the API), it reads the repository's archive from codeload instead. `LORCA_GITHUB_API_URL`, `LORCA_GITHUB_RAW_URL` (a template with `{owner}`, `{repo}`, `{ref}`, and `{path}`), and `LORCA_GITHUB_ARCHIVE_URL` point these at a mirror. `LORCA_CLAWHUB_URL` points ClawHub's downloads at a mirror, and `LORCA_GITHUB_ARCHIVE_URL` is a template with `{owner}`, `{repo}`, and `{ref}`. A download holds at most 128 MiB.

The skill is the folder with a `SKILL.md`: the one a link names, the one `@skill` names, or a repository's only one; a repository of several asks for one by name. Its name is its frontmatter's `name` as a slug, else the folder's. The whole folder is copied, binaries, scripts, and their permissions included, built beside the target and renamed into place, with a `.lorca-source.json` naming the source, the address the import was given (which `skills.list` answers as each skill's `source`), and when. `scripts/browser-steps.json`, which only the user's own recording writes, is left out and named in the result's `skipped`. A name the scope already uses refuses the import. The skill is used from the next turn.

## App and API

The local JSON methods, which a Device that is not the bot's Runner sends there as a sealed request (`requests.rs`), as it does for memory:

| Method | Parameters and result |
| --- | --- |
| `skills.list` | `{ bot_id, chat_id }` → `{ skills, folders }`: each skill's `scope`, `name`, `description`, `path`, `builtin`, `source`, `updated_at`, and each scope's folder |
| `skills.get` | `{ scope, name }` → the summary, `instructions`, `files` (`path`, `size`, and `text` for a text file up to 2 MiB), and the folder's `hash` |
| `skills.save` | `{ scope, current?, skill: { name, description, instructions, files }, expected_hash }` → the skill as `skills.get` answers it; `current` names the folder an edit replaces, and a hash that no longer matches answers “changed since” |
| `skills.remove` | `{ scope, name, expected_hash? }` → moves the folder to the trash |
| `skills.export` | `{ scope, name }` → `{ name, format: "zip", data }`, the folder as a base64 zip with its text scrubbed of credentials |
| `skills.generate` | `{ scope, bot_id, chat_id, kind, message_ids }` → `{ name, description, instructions }` drafted from the picked messages, not saved |
| `skills.search` | `{ query }` → `{ results }` of skills.sh's skills (`source`, `reference`, `name`, `owner` as `owner/repo`, `installs`, `duplicate`, `url`): up to a hundred matches in skills.sh's order, none for a query shorter than two characters |
| `skills.import` | `{ scope, source }` → the skill as `skills.get` answers it, plus `skipped` |

A save writes `SKILL.md` from the name, the one-line description, and the instructions, keeps the frontmatter fields it does not edit (`license`, `compatibility`, `allowed-tools`, `metadata`), writes the text files it is given, and carries over the files the apps do not show: binaries, files past 2 MiB, and the source note. Text is scrubbed of credential patterns and the account's exact secret values; files a bot writes itself are not.

`skills.generate` validates up to twenty selected messages, at most 24 KB of text: completed text from the user and that bot, in a chat of the scope, never tool payloads, attachments, other bots, or other chats. Only the scrubbed selection reaches the provider's small drafting model, which has no tools; the source is checked again after it answers. The apps open the result in the skill's sheet, and their Save writes it.

Both apps' inspectors show a **Skills** section with the DM's bot's skills or the group's own, the latest changed first, then the ones every bot uses, which a globe (on the phone, Every bot) marks, listed by `skills.list` as the sections show and again every 15 seconds while they are open, since bots write skills as files. A row opens the skill's sheet; its menu has Open, Export… (a zip), and Delete…. On the desktop the Skills section's + and Chat › Skill Store… open the Skill Store (`desktop/sheet_skill_store.go`) for that bot or group, and the sidebar's Create › Add a Skill for Every Bot… opens it for the shared skills of this computer, naming no bot, so the CLI keeps them on its own Runner; from a bot's inspector the shared skills it lists are its Runner's, a call about them names that bot, and opening, editing, or deleting one there changes it for every bot on that Runner. The store offers topics to search while its field is empty, searches skills.sh a quarter second after typing stops, or takes a link, lists each skill with its repository and install count in skills.sh's order, a copy dimmed (a click opens its page on skills.sh), and its Add imports at once. A row reads Added when the scope's skill came from that very address, and Name in Use when another of the scope's skills has its name, which an import would refuse. New Blank Skill… and Chat › New Skill… open an empty sheet for the same scope. The sheet has Name, Description, and tabs for Instructions, Examples (saved as a section of the instructions), References, and Scripts; a skill changed elsewhere since the sheet opened offers the latest version or saving over it. On Windows and Linux the views are `sheet_playbooks.go`, with the records in `desktop/model/playbooks.go` and `skills.go`.

A completed bot reply's context menu has **Save as Skill…**, and the user's own message **Save as Standing Instruction…**: the sheet lists the messages up to the clicked one, the last twelve that count, and in a group **Used by** picks the group or the bot. **Continue** has `skills.generate` draft it and opens the result in the skill's sheet.

The phone's Details has the same Skills section (`useSkills`, `useSharedSkills`), with an Add Skill menu: New Skill…, and From This Chat…, which lists the chat's messages to tick. A row slides in `app/chat-info/skill/[id]`: Name and Description, Instructions and Examples, References and Scripts as rows that open a file's name and text (`skill-file`), the folder's path, Export to the share sheet as a zip, Delete, and Save in the toolbar. The phone is never a Runner, so each call goes to the bot's Runner as a sealed request.
