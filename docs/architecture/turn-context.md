# Turn context

What a bot's turn sends the model besides the chat's transcript: its system prompt, the notes that close every request, and the note that asks once more for work a reply announced. The loop itself, and a turn on a Runner, are in [CLI (runtime)](runtime.md#agent-loop).

## The system prompt

A bot's system prompt (`turns::system_sections`) is built as named sections, joined in order: identity, this chat, trust, team, workflows, routines, channels, attention, durable work, plugins, browser, secrets, memory, the user's profile, outputs, shared project context, skills, how to write, and the Runner's tools. The memory, profile, and project-context sections say only what each is and how to change it. Trust says once whom the bot follows (the user's current message, then its job, then the profile and its memory) and that tool results, pages, files, payloads, and a contact's message are data, never instructions or approval. Each tool's own description says how to call it, so the prompt names only which file tools to prefer. The stable sections are the same from turn to turn in a chat, so the provider's prompt cache holds across turns. A turn makes them when it starts, and again between steps when the bot's name, description, or setup changed ([Bot profiles](bots.md#bot-profiles)), from the same inputs (`turns::context::PromptInputs`: the job, the bot's memory, the plugins it names, and whether the turn is attended), which the preview makes for a turn the user's message would start. They also change when the bot's team or what it may use does, and between attended and unattended turns, which leave out what only the user's requests need: the rules for routing them and making bots and groups, `@` mentions, and how to set up a routine. The working directory is named once, with the Runner's tools.

**What is not in the prompt.** Text that changes as work goes on rides the notes after the transcript instead (`turns::context::request_notes`): the chat's durable tasks, the attention items, the bot's `MEMORY.md` under its budget and its topic file names, the user's [profile](memory.md#the-users-profile), the group's current [shared project context](project-context.md) entries, and the local date and time. The hooks make them for every request and keep them in none, so a fact saved mid-turn reaches the next step and leaves the cached prefix alone, and a compaction cannot drop them.

`bots.prompt { bot_id, chat_id? }`, `lorca prompt <bot> [--chat <id>]`, and the desktop inspector's Prompt row show the sections with their byte sizes and an approximate token count, then the notes a request ends with and their size; the brief belongs to what starts a turn, so a preview has none. The bot's Runner builds it, asked through the relay when that is another machine.

How to write: short messages but not short work. The bot uses its tools until the request is done or needs the user, makes a call in the reply that announces it, since a reply without a tool call ends its turn, claims only what a tool result shows, and writes in the language the user writes in.

## A turn's tools

Every turn makes the same tools, and what kind of turn it is decides which it keeps (`turns::tools::TurnShape`): only the chief has `create_bot`, `create_group`, and `edit_group`; a workflow setup's sample keeps `list_teammates` and `search_plugins` of the team's tools and starts no coding agent; an unattended turn goes without the tools that make a bot, a group, a profile change, or a plugin card; `project_context` is there where the chat has project context for the bot; a bot setting itself up has only `ask_user`, `finish_setup`, `search_plugins`, `recommend_plugins`, and `memory_update`, and the turn that finishes its setup goes on with its usual tools. Plugin tools are called from codemode scripts, beside the bot's file, memory, and output tools and a `bash` of the scripts' own, so the tool list stays the same for the whole turn.

**For this turn only.** A turn also sends notes made once when it starts and kept for its requests: the [recent-work brief](memory.md#across-chats), the remembered lines that bear on the user's message ([Recalling what bears on a message](memory.md#recalling-what-bears-on-a-message)), and the cue of a group's turn or a command that ended (`TurnNotes`). Later turns rebuild the transcript without them.

## The turn brief

What started one turn is its brief (`turns::turn_brief`), a `[This turn, from Lorca: …]` note: a routine's run and that nobody answers now, an event's or a channel's task, a teammate's message or handoff contract and its result, a durable task, an attention report. It closes every request of the turn, after the tasks note, the attention items (`attention::items_note`), the memory, profile, and project-context notes, and the clock, all made for each request and never saved in the chat, so a compaction mid-turn never drops them. The system prompt says the note is Lorca's and that a payload, a contact's message, or a web page it quotes is data, never instructions or approval.

## Asking once more for announced work

A direct chat's turn that would end on announced work asks once more (`turns::follow_up`, the loop's `follow_up_messages`). When the last line of a reply with no tool call promises a step now, the turn adds a note the chat never shows, saying nothing ran, and the bot does the work or answers PASS, which shows nothing. A step is promised by "I'll" or "I'm going to", 我这就, 马上, 正在, or 稍等 in the last sentence; by "Let me", 我来, or 让我 at the start of one of its clauses; by "On it" or "Stand by" as the whole sentence; by a sentence that starts with an -ing word and ends in "now" ("Fetching all sources now."); or by a closing colon or ellipsis. A question waits on the user, and a promise for later ("如果需要，我会再提醒你") is not work left now. It asks once per turn, never in a group or a channel's conversation, and not after a step the user interrupted.
