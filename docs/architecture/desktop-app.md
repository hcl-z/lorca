# Desktop app

`desktop/` is the desktop app for macOS, Windows, and Linux, a Go program built with [MyGo](https://github.com/egoist/mygo) and drawn with MyGo's native UI toolkit (`github.com/egoist/mygo/ui`): the windows, menu bars, tray icon, notifications, the CLI, and every view are Go. The macOS build is for Apple silicon, as `Lorca.app` (`app.lorca`). The three platforms share one set of windows, panes, sheets, menus, and words, with Lucide icons standing in for SF Symbols (`icons_lucide.go` maps each symbol name the models and views use). `go.mod` pins MyGo 0.4.5 and its command line as a Go tool (`go tool mygo`). A coding agent's output is drawn by MyGo's terminal plugin, whose libghostty-vt `mygo build` puts into the app; the macOS app therefore requires macOS 13 (`minimumSystemVersion` in `mygo.config.ts`).

- **Model** (`desktop/model`): the AppStore, models, formatters, and demo reply engine (`LORCA_MOCK=1`) in Go. `store.go` holds the account as the CLI reports it and makes every change through the CLI's methods; `wire.go` reads the CLI's JSON, `format.go` writes times, sizes, and schedules for display, `mcp.go` reads and writes a Runner's `mcp.json` entries, and message Markdown is goldmark's tree folded into the blocks and spans `crates/markdown` produces (`markdown.go`), with bare links found by the crate's autolink rules (`autolink.go`). The store lives on the main thread: CLI events and the answers of its asynchronous calls come back through one ordered queue the app runs there (`post` in `window.go`), and every window redraws after each.
- **Words** (`desktop/l10n`): `L("…")` and `Lc("…", "context")` are the English text as the key, looked up in `zh.go`; `bun run l10n` checks the table against the Go sources, as it does the phone's. The language is the one picked in Settings, else the system's.
- **The Go host** (`desktop/*.go`): `launcher.go` finds the CLI (`LORCA_CLI`, the app's `resources/bin`, `~/.local/bin`, `~/.cargo/bin`, then `PATH`), probes the port, and starts `lorca serve --port … --parent-pid … --ready-stdout` when nothing answers, restarting it with a backoff; `client.go` holds the one websocket to the CLI, with the token from the CLI's data directory ([Protocols](protocols.md#app--cli-local-ws)), and reconnects it. `app.go` picks the window: onboarding until the CLI reports an identity, then the main window, and while onboarding is up, Settings as a small window of General and Advanced. A computer without an identity waits for the CLI's answer past the 2.5-second loading deadline, which a CLI's first start (a new binary, a new database) can outlast; a startup failure or 10 seconds without an answer opens the main window on the offline recovery controls. With a tray icon, closing the windows leaves the app running, since the bots on this computer run with it. `tray.go` puts that icon in the menu bar on macOS (a template image, so the system tints it; Lorca Dev keeps its yellow icon) and in the notification area on Windows and Linux. Its menu lists the unread chats under "N unread" (eight, then "N more chats…"; a row opens the chat), Attention when anything waits, then Open, New Bot…, Settings…, and Quit; it is rebuilt when the list changes. The unread total is the number beside the icon on macOS and in the tooltip elsewhere, and the Dock or launcher badge, with muted chats left out of all three ([Notifications](notifications.md)). General › App Icon has two switches, both on to start with: whether the icon is shown (`ShowsTrayIcon`, applied at once; on Windows and Linux, with it off closing the last window quits the app) and whether the unread total is shown on the Dock or launcher icon and beside the tray icon (`UnreadBadge`). `files.go` opens the system's file dialogs and reads attachments and bot images from their paths, `avatar.go` makes a bot's image a square PNG of at most 512 px, and `prefs.go` keeps the preferences (selection, pane widths, appearance, language, send key, the CLI port) in `preferences.json` in the app's data folder. `openExternal` (`host.go`) opens only http(s) links with a host and mailto links, since links from bots, plugins, and the marketplace reach it. A web link in a bot's message is drawn as a source chip with its site's icon (`sources.go`): [Web links in messages](links.md).
- **Views**: MyGo's views are immediate: a window's view function builds its elements every frame from the store and the window's own state, and MyGo keeps what an element owns (a field's text, a list's scroll, a hover) by its place and key. Constructors return `ui.Element` values that belong to that build pass; helpers take the current `*ui.Context` as an argument and return elements separately from their action results. Keys reach stateful controls before construction through `c.Key(...)`. Editable text binds to persistent state. Public click, shortcut, change, and submit queries apply pending bound input first, so inline handlers see edited values in the same build pass. Simple settings switches and row-click decisions use inline polling after control configuration. Sidebar navigation chooses a chat or settings row on pointer press, and MyGo rebuilds that choice before painting its focus colors, so clicking a different row from the composer shows the new selection in the first frame; button actions activate on release. Changes to routines, the MCP server list, tool visibility, and model selection use `OnChange` callbacks beside their controls, which run after the view and its bound inputs are built. The MCP form's mode and server type also use `OnChange`, so switching carries the latest edits forward and selecting the current mode keeps the draft; each field retains its previous text until its change is observed, so pasted JSON restores the field and opens the JSON editor. `window.go` gives every window its frame: the theme, the view, and its sheets. `theme.go` holds the design tokens every view draws with: a light and a dark palette, the radii (`radiusXS` to `radiusSheet` and `radiusCapsule`), control heights (`controlSmall`, `controlRegular`, `controlLarge`, `fieldHeight`), spacing steps (`space1` to `space5`), and text sizes. The look is monochrome: neutral surfaces, ink (near-black in light, near-white in dark) for the default button, the user's bubbles, and a switch that is on, a neutral fill for the selected row, and bordered cards and plain buttons; the desktop's accent colors focus, links, and mentions, and bots keep their system colors. A pending permission card carries an Approval needed badge and puts its first choice in ink. A row's actions sit on small chips and lead with a symbol (`actionLookFor` in `controls.go`, keyed by their localized words): Edit…, Copy, Show, Open, Reload, Retry, and Reset are the symbol alone with their words as tooltip and label, the others the symbol and their words, and a row's push button takes the same symbol, and a chat's header leads with its bots' avatars. The sidebar footer's sun or moon button and View › Use Dark/Light Appearance (Ctrl+Shift+L) switch the appearance by saving the opposite of the one showing; General's Appearance picks System, Light, or Dark. `mainwindow.go` is the main window's three panes and the selection; `sidebar.go` the chats and the settings panes with their search (`settings_search.go`); `chat.go` the transcript, a `ui.List` that follows the newest message, loads older pages as it nears the top, and draws each message, tool, handoff, and day row, a message's text one selection that a drag runs across (MyGo's `Selectable` on its Markdown); `cards.go` the permission and command cards; `agents.go` a coding agent's card and its transcript ([Coding agents](coding-agents.md#the-card)); `composer.go` the composer, a text area in a solid capsule over the `glass` plugin's backdrop blur, with a hairline that darkens while it has the keyboard, a round Attach button at its start and an ink Send disc at its end (32 DIPs each), growing from one line to eight, when it becomes a rounded rect. Draft edits and changes to the composer's measured height request the next display frame until the transcript's bottom inset matches it, so clearing a multiline draft keeps the latest reply just above the collapsed composer without waiting for more input. It has mentions (in their bot's color as typed), replies, attachments, and pasted images; `inspector.go` the inspector, and `sheet_review.go` its Waiting for review section and the review sheet ([Review queue](review-queue.md#in-the-apps)); `palette.go` the command palette; `runningtasks.go` the running tasks popover; `attention.go` the Attention popover beside it, ([Coordinator attention](attention.md#in-the-apps)); `settings*.go` the settings panes; `marketplace*.go` the marketplace, with a service's [named accounts](integrations.md#stable-account-instances) on its page; `onboarding.go` onboarding; and `sheet_*.go` the sheets. The shared controls (`controls.go`) and the rows and cards (`sections.go`) draw with the tokens: a card is captioned in sentence case over a bordered, 12-DIP-round fill, its rows at least 36 tall with 14-DIP margins where the dividers stop; clickable rows fill under the pointer, an editable value fills under it and shows a field while editing, and a row's pop-up is a right-aligned value with chevrons, at most 170 wide, rather than a box. The controls move with the pointer: a fill or border fades over 120 ms (`controlFade`), a button held down sinks a few percent on a spring in frames that only paint (`sinkWhenPressed`), a switch's knob stretches while held and slides on a spring, a field's focus border and halo fade in and out, the segmented control's selection and a Copy button's icon change smoothly, and sheets and popovers open from a little smaller and lower. With Reduce Motion the fades stay and the sinking and sliding happen at once. The inspector's header says Details. A sheet (`overlay.go`) is the key window: it dims the window behind it and takes its clicks and keys, Escape cancels it and Return presses its default button; its panel sits in the middle of the window, and a press outside the panel cancels it as Escape does, except an alert's, which only its buttons answer (`pressedBackdrop` in `overlay.go`), and closing one hands the keyboard back to what had it. The composer has no Dictate button and General no Dictation section: Windows and Linux give the app no speech recognizer it uses.
- **Outputs** (`outputs.go`, `model/outputs.go`): the inspector's Outputs section, hidden while the chat has none, shows the three latest outputs and View all; a row opens the output's sheet with a preview of an image or the first 64 KB of a text file (read off the main thread), the check, the versions, Save As… and Open, or Try Again when the file could not be fetched. `Store.Outputs` lists a shown chat's outputs once and follows message events. Open and Save As… ask the CLI for the file under its own name (`files.path` with `named: true`); Save As… writes through a temporary file beside the destination, so a failed copy leaves what was there. In the transcript an output is a card of its own (`outputCard` in `chat.go`). See [Outputs and evidence](outputs.md).
- **Limits** (`desktop/model/budgets.go`, `sheet_budget.go`, `sheet_connector_limits.go`): the snapshot's `budgets` and `budgets.changed` fill the store. The DM inspector's Limits row, the routine sheet's, and the plugin sheet's Call limit row are `disclosureRow`s that open the Limits and Call Limit sheets. The Limits sheet's fields are its own until it closes; its calls go out in order (the limits, then Resume) on the ordered main-thread queue, and a reply for a closed sheet is dropped: [Budgets and connector limits](budgets.md#in-the-apps).
Routines (`sheet_routine.go`, `model/routine_health.go`) and the Devices pane's Background service row follow the same rules; see [Routines](routines.md#the-apps). So do channels (`sheet_channel.go`, `channelRow`): [Channels](channels.md#in-the-apps).

A bot’s DM Profile card has the Access row (`disclosureRow`), which opens the same [Access sheet](bot-permissions.md#requests-to-the-user) (`sheet_access.go`): the plugins with their levels and tool checkboxes, then Files and Shell commands under the Runner's name. The sheet keeps the choices across frames and keys each plugin's row by its id; the tools the Runner sends arrive on the main-thread queue and keep what the user already chose, and a dismissed sheet ignores them. An access request in the chat offers Edit Access… and Dismiss, and the Plugins section reads No access for a plugin the bot may not use.
- **Workflow feedback** ([subject](feedback.md#in-the-apps)): Give Feedback… on a bot's message, the inspector's Feedback section, and the feedback, suggestion, and change sheets (`sheet_feedback.go`), over typed models and calls in `model/feedback.go`. The inspector keeps each bot's last `feedback.list` with its memory, and the sheets read it, so a `feedback.changed` refreshes them all; a closed sheet drops a late reply.
- **Title bar**: each pane of the main window has a header over its own background: the sidebar's holds the sidebar and Create buttons the content's the title and subtitle, back and forward, the Device picker, and running tasks, and the inspector's its toggle. A chat's transcript runs under the content's header,: the header draws macOS's hard scroll edge (MyGo's `glass.ScrollEdge`, the transcript frosted under it with a hairline below) once the transcript scrolls from its top or the pointer is over the header, and nothing before. The main window shows no system material: the sidebar, content, and inspector each paint their own token color on every platform. Each pane divider has its own key and uses captured pointer drag state to resize across the adjacent panes until release, when its width is saved in preferences. The sidebar stays between 232 and 340 DIPs and collapses when dragged well past its minimum; the inspector stays between 268 and 320 DIPs. The headers are the title bar: the main window hides its own (`TitleBarHidden`, 52 pixels tall like the headers), keeps the window controls over the headers, and the headers drag the window (`DragWindow`). On macOS the traffic lights sit in the sidebar's header (`TrafficLightPosition` at 19, 19). On Windows and Linux MyGo puts the controls in a top corner: on Windows minimize, maximize, and close at the right, drawn as Windows 11 draws them, on Windows 10 too, and on Linux GTK's own title buttons wherever the desktop's button layout puts them, or none. The rightmost header and the sidebar and Create buttons keep clear of them by the insets `c.TitleBar()` reports. Onboarding hides its title bar too: its page fills the window under the window controls, the close button alone on Windows since the window can neither minimize nor maximize, and its background drags the window. The small settings window keeps the system's title bar. A window's title, which the taskbar and Alt+Tab show, is its content's title (the chat's, the settings pane's, Settings in the small window) followed by ` - Lorca`, the app's name, which stands alone where there is no title of its own (`setTitle` in `window.go`). On Windows and Linux every window's menu bar stays out of sight until Alt or F10 takes the keyboard to it (MyGo's `AutoHideMenuBar`), and its shortcuts work all along; the main window has no room for a bar on Windows, so there Alt and F10 open its menus from the window's top-left corner.
- **Skills** (`model/playbooks.go`, `sheet_playbooks.go`): the inspector's Skills section, the skill sheet, and Save as Skill ([Playbooks](playbooks.md#app-and-api)). Export runs MyGo's save dialog away from the view and posts a failure back to the main thread.
- **Templates** (`sheet_template_share.go`, `sheet_template_import.go`, `settings_sharedlinks.go`, `template_files.go`): File › Share as Template… and New Bot from Template… open the [template sheets](templates.md#in-the-apps), and Settings › Shared Links lists the account's links; `template_files.go` asks the system's Open and Save dialogs for a path, and the CLI reads and writes the file. `urlSchemes` in `mygo.config.ts` declares `lorca://` (`lorca-dev://` for Lorca Dev), which the installer registers on Windows, the desktop entry on Linux, and Info.plist on macOS; `OnOpenURL` takes such a link with the launch or from a second instance and keeps it until the account and CLI are up.
- **Questions** ([subject](questions.md#in-the-apps)): the transcript's question card (`ask_card.go`) with its options, Other, Submit, and Skip. A code block in a message has a header with its language and Copy, While the pointer is over a finished message, Reply and Copy float on a pill beside its bubble (`message_actions.go`), with Edit on the user's latest message and Regenerate on the bot's reply to it where that exchange can [run again](runtime.md#running-a-reply-again) (`model/rerun.go`); Edit takes the message into the composer, which says Editing your message, gives back its draft on Escape, takes no new files, and marks the message Edited once sent. The pill is laid out of the flow so nothing moves: at the bubble's trailing side for a bot and its leading side for the user, or straddling its top corner where there is no room beside it, at its bottom when its top is under the header, never past the composer, and always inside the transcript (`placeActions`). The pointer can cross from the bubble onto the pill, which stays until the pointer is on neither.
- **Secrets** ([subject](secrets.md#in-the-apps)): the transcript's secret card (`secretCard` in `cards.go`) and Settings › Secrets with its sheet (`settings_secrets.go`).
- **Commands** (`commands.go`): one table gives the menu bar (File, Edit, View, Chat, Window, Debug, Help, with Settings, Quit, About, and Check for Updates in File and Help) and the command palette's titles and enabled states, and the menu bars follow the table's states as the windows redraw. Ctrl stands where macOS has ⌘; Ctrl+1 to Ctrl+9 are the main window's own shortcuts, since the Windows menu bar keeps no hidden items. While a sheet is up only the app's own commands (Quit, About, Help, Check for Updates) run, as a sheet takes a Mac window's commands.
- **Updates** (`updater.go`): MyGo's updater plugin It checks once a day in the background, and a window of its own shows a new version's release notes with Install Update, Remind Me Later, and Skip This Version, the download's progress, and the offer to relaunch. It installs releases signed with the update key, as a delta from the running version when the release has one, and keeps the user's choices in `updater.json` in the app's data directory. **Check for Updates…** opens that window, and General has the version, the last check, and switches for automatic checks and automatic installs, which follow the plugin's changes (`updater.OnChange` redraws the windows). The window speaks the language picked in Settings, else the system's; a new pick reaches it at the next launch. Its releases are this repo's, tagged `desktop-vX.Y.Z` (`updates` in `mygo.config.ts`, with the public key). The repo's latest release stays the CLI's, so release builds find the newest `desktop-v` release through the GitHub API (MyGo's `tagPrefix`), and read its update manifests. `bun run release-desktop` uploads to a draft of the version through `go tool mygo build -upload`, here or in the Release desktop workflow (`.github/workflows/release-desktop.yml`), which a `desktop-vX.Y.Z` tag or a run by hand starts: it drafts the release with the changelog's section and builds Windows x64, Linux x64, and Linux arm64 side by side on Ubuntu and macOS arm64 on a Mac runner, which signs it ad hoc and makes its disk image, and publishing the draft, without making it the latest release, releases the update. The app has its own version, `version` in `desktop/mygo.config.ts`, apart from the Mac app's, and its own release notes, the version's section of `desktop/CHANGELOG.md`: [docs/releasing-desktop.md](../releasing-desktop.md). A build that cannot write where it is installed, `mygo dev`'s or the Debian package's in `/opt`, leaves the menu item and the General rows out.
- **Development and builds**: `bun run desktop` builds the CLI and runs `go tool mygo dev` (Lorca Dev, `app.lorca.dev`, with `~/.lorca-dev` and port 4863), which rebuilds and relaunches the app on a Go change; `LORCA_MOCK=1` runs the demo instead of the CLI, and `LORCA_PORT` points the app at a CLI on another port. `go tool mygo vet .` in `desktop/` runs Go vet and checks for build values stored in state or captured by workers. `go test ./...` (slow; how to run a part of it: [Testing the desktop app](development.md#testing-the-desktop-app)) runs the model's tests and the views' tests, which build the windows over the demo's store in MyGo's offscreen tester (`ui.NewTester`), click and type into them, and check what they show; with `LORCA_RENDER=<folder>` they also write each frame they look at as a PNG. `LORCA_E2E_PORT=<port> LORCA_E2E_SERVER=<base URL>` adds `TestE2EAgainstCLI`, which drives the main window over a CLI with an identity on that port: it adds an OpenAI-compatible server at that URL as a custom provider through its sheet, runs the first bot on it, and checks the reply that streams back. `bun run desktop:build [platforms]` builds the CLI for each platform into `desktop/resources/<goos>-<goarch>/bin` (static musl builds for Linux, with cargo-zigbuild, as the CLI releases are; cargo on a Mac for macOS) and runs `go tool mygo build -platform`; MyGo needs no cgo, so Windows and Linux build from any computer, while `darwin/arm64` builds on a Mac, which links its CLI, signs the app, and makes the disk image. A Mac builds macOS on Apple silicon and Windows and Linux on x86-64 by default. `mygo.config.ts` signs the macOS app ad hoc unless `SIGN_IDENTITY` names an identity, and notarizes it with the notarytool profile `NOTARY_PROFILE` (in the keychain `NOTARY_KEYCHAIN`) only when that is set; releases set neither.

## Shared project context

A group's inspector has the Project section, and a row opens the same entry sheet (`project.go`): the entries a row each, a + menu that adds one, Check Now under a link, Open for a file, and a conflict alert when another Device saved first. `model/project_context.go` makes the `projects.*` calls; their replies come back on the store's main-thread queue, a sheet closed meanwhile ignores them, and `projects.changed` lists the group again. [Shared project context](project-context.md#the-apps) describes both apps.

## Workflows

The last onboarding page has Choose a Workflow… under Open Lorca, and the marketplace lists Workflows first; a workflow's page is among the marketplace pages in `desktop/workflows.go` over `desktop/model/workflows.go`: [Workflow onboarding](workflows.md#the-apps).
