# Desktop app

`desktop/` is the desktop app for macOS, Windows, and Linux, a Go program built with [MyGo](https://github.com/egoist/mygo) and drawn with MyGo's native UI toolkit (`github.com/egoist/mygo/ui`): the windows, menu bars, tray icon, notifications, the CLI, and every view are Go. The macOS build is for Apple silicon, as `Lorca.app` (`app.lorca`). The three platforms share one set of windows, panes, sheets, menus, and words, with Lucide icons standing in for SF Symbols, which the phone app draws too (`icons_lucide.go` maps each symbol name the models and views use). `go.mod` pins MyGo 0.4.5 and its command line as a Go tool (`go tool mygo`). A coding agent's output is drawn by MyGo's terminal plugin, whose libghostty-vt `mygo build` puts into the app; the macOS app therefore requires macOS 13 (`minimumSystemVersion` in `mygo.config.ts`).

- **Model** (`desktop/model`): the AppStore, models, formatters, and demo reply engine (`LORCA_MOCK=1`) in Go. `store.go` holds the account as the CLI reports it and makes every change through the CLI's methods; `wire.go` reads the CLI's JSON, `wire_event.go` decodes each event frame once into a typed event (`DecodeEvent`, after `crates/cli/src/events.rs`, which a test holds it to; an unknown or malformed frame is logged and applies nothing), which the store applies, `format.go` writes times, sizes, and schedules for display, `mcp.go` reads and writes a Runner's `mcp.json` entries, and message Markdown is goldmark's tree folded into the blocks and spans `crates/markdown` produces (`markdown.go`), with bare links found by the crate's autolink rules (`autolink.go`). The store lives on the main thread: CLI events and the answers of its asynchronous calls come back through one ordered queue the app runs there (`post` in `window.go`), and every window redraws after each.
- **Words** (`desktop/l10n`): `L("…")` and `Lc("…", "context")` are the English text as the key, looked up in `zh.go`; `bun run l10n` checks the table against the Go sources, as it does the phone's. The language is the one picked in Settings, else the system's.
- **The Go host** (`desktop/*.go`): `launcher.go` finds the CLI (`LORCA_CLI`, the app's `resources/bin`, `~/.local/bin`, `~/.cargo/bin`, then `PATH`), probes the port, and starts `lorca serve --port … --parent-pid … --ready-stdout` when nothing answers, restarting it with a backoff; `client.go` holds the one websocket to the CLI, with the token from the CLI's data directory ([Local websocket](local-ws.md)), and reconnects it. `app.go` picks the window: onboarding until the CLI reports an identity, then the main window, and while onboarding is up, Settings as a small window of General and Advanced. A computer without an identity waits for the CLI's answer past the 2.5-second loading deadline, which a CLI's first start (a new binary, a new database) can outlast; a startup failure or 10 seconds without an answer opens the main window on the offline recovery controls. With a tray icon, closing the windows leaves the app running, since the bots on this computer run with it. `tray.go` puts that icon in the menu bar on macOS and in the notification area on Windows and Linux: the app's own icon in color (`assets/tray.png`, the app icon at 64 px), and Lorca Dev's yellow one for Lorca Dev. Its menu lists the unread chats under "N unread" (eight, then "N more chats…"; a row opens the chat), Attention when anything waits, then Open, New Bot…, Settings…, and Quit; it is rebuilt when the list changes. The unread total is the number beside the icon on macOS and in the tooltip elsewhere, and the Dock or launcher badge, with muted chats left out of all three ([Notifications](notifications.md)). General › App Icon has two switches, both on to start with: whether the icon is shown (`ShowsTrayIcon`, applied at once; on Windows and Linux, with it off closing the last window quits the app) and whether the unread total is shown on the Dock or launcher icon and beside the tray icon (`UnreadBadge`). `files.go` opens the system's file dialogs and reads attachments and bot images from their paths, `avatar.go` makes a bot's image a square PNG of at most 512 px, and `prefs.go` keeps the preferences (selection, pane widths, appearance, language, send key, the CLI port) in `preferences.json` in the app's data folder. `openExternal` (`host.go`) opens only http(s) links with a host and mailto links, since links from bots, plugins, and the marketplace reach it. A web link in a bot's message is drawn as a source chip with its site's icon (`sources.go`): [Web links in messages](links.md).
- **Views**: MyGo's views are immediate: a window's view function builds its elements every frame from the store and the window's own state, and MyGo keeps what an element owns (a field's text, a list's scroll, a hover) by its place and key. Constructors return `ui.Element` values that belong to that build pass; helpers take the current `*ui.Context` as an argument and return elements separately from their action results. Keys reach stateful controls before construction through `c.Key(...)`. Editable text binds to persistent state. Public click, shortcut, change, and submit queries apply pending bound input first, so inline handlers see edited values in the same build pass. Simple settings switches and row-click decisions use inline polling after control configuration. Sidebar navigation chooses a chat or settings row on pointer press, and MyGo rebuilds that choice before painting its focus colors, so clicking a different row from the composer shows the new selection in the first frame; button actions activate on release. Changes to routines, the MCP server list, tool visibility, and model selection use `OnChange` callbacks beside their controls, which run after the view and its bound inputs are built. The MCP form's mode and server type also use `OnChange`, so switching carries the latest edits forward and selecting the current mode keeps the draft; each field retains its previous text until its change is observed, so pasted JSON restores the field and opens the JSON editor. `window.go` gives every window its frame: the theme, the view, and its sheets. `theme.go` holds the design tokens every view draws with: a light and a dark palette, the radii (`radiusXS` to `radiusSheet` and `radiusCapsule`), control heights (`controlSmall`, `controlRegular`, `controlLarge`, `fieldHeight`), spacing steps (`space1` to `space5`), and text sizes; a scroll container's thumb is 4 DIPs of a faint `Scrollbar` color, shown under the pointer (6 DIPs and stronger with High Contrast), and a message's bubble holds its text and files alone, its time in the transcript's day rows. The look is monochrome: neutral surfaces, ink (near-black in light, near-white in dark) for the default button, the user's bubbles, and a switch that is on, a neutral fill for the selected row, and bordered cards and plain buttons; the desktop's accent colors focus, links, and mentions, and bots keep their system colors. A pending permission card carries an Approval needed badge and puts its first choice in ink. A row's actions sit on small chips and lead with a symbol (`actionLookFor` in `controls.go`, keyed by their localized words): Edit…, Copy, Show, Open, Reload, Retry, and Reset are the symbol alone with their words as tooltip and label, the others the symbol and their words, and a row's push button takes the same symbol. The sidebar footer's sun or moon button and View › Use Dark/Light Appearance (Ctrl+Shift+L) switch the appearance by saving the opposite of the one showing; General's Appearance picks System, Light, or Dark. `mainwindow.go` is the main window's three panes and the selection; `sidebar.go` the chats (the a row's avatar, name, and preview with a dot while unread, sentence-case group headers, and a footer of Settings, this computer, the appearance, and a Marketplace capsule) and the settings panes with their search (`settings_search.go`); `chat.go` the transcript, a `ui.List` that follows the newest message, loads older pages as it nears the top, folds a message taller than a fixed height to its head under a fade with Show more, and draws each message, tool, handoff, and day row, a message's text one selection that a drag runs across (MyGo's `Selectable` on its Markdown); `cards.go` the permission and command cards; `agents.go` a coding agent's card and its transcript ([Coding agents](agent-cards.md)); `composer.go` the composer, a text area in a solid capsule over the `glass` plugin's backdrop blur, with a hairline that darkens while it has the keyboard, a round Attach button at its start and an ink Send disc at its end (32 DIPs each), growing from one line to eight, when it becomes a rounded rect. Draft edits and changes to the composer's measured height request the next display frame until the transcript's bottom inset matches it, so clearing a multiline draft keeps the latest reply just above the collapsed composer without waiting for more input. It has mentions (in their bot's color as typed), replies, attachments, and pasted images; `inspector.go` the inspector: who the chat is with, large and centered (a DM's bot avatar, which opens its look, its name, and its Runner online or offline, which opens that Runner; a group's avatars, name, and bot count), over a row of icon tabs (`iconTabs` in `controls.go`) that split its sections: Activity (reviews, tasks, outputs, feedback, or a sentence and New Task while there are none), Bot for a DM (Profile; Runs with: provider, model, thinking, credential; This chat: context, spend, limits, prompt) or Members for a group (its bots, Group, Project, where turns run), Skills (a DM's Memory and About you, then skills and plugins), and for a DM Routines (routines, channels); the tab holds from chat to chat, and `sheet_review.go` its Waiting for review section and the review sheet ([Review queue](review-queue.md#in-the-apps)); `palette.go` the command palette; `runningtasks.go` the running tasks popover; `attention.go` the Attention popover beside it, ([Coordinator attention](attention.md#in-the-apps)); `settings*.go` the settings panes; `marketplace*.go` the marketplace, with a service's [named accounts](integrations.md#stable-account-instances) on its page; `onboarding.go` onboarding; and `sheet_*.go` the sheets. The shared controls (`controls.go`) and the rows and cards (`sections.go`) draw with the tokens: a card is captioned in sentence case over a bordered, 12-DIP-round fill, its rows at least 36 tall with 14-DIP margins where the dividers stop; clickable rows fill under the pointer, an editable value fills under it and shows a field while editing, and a row's pop-up is a right-aligned value with chevrons, at most 170 wide, rather than a box. The controls move with the pointer: a fill or border fades over 120 ms (`controlFade`), a button held down sinks a few percent on a spring in frames that only paint (`sinkWhenPressed`), a switch's knob stretches while held and slides on a spring, a field's focus border and halo fade in and out, the segmented control's selection and a Copy button's icon change smoothly, and sheets and popovers open from a little smaller and lower. The views move too (the motion tokens in `controls.go`): a side pane opens and closes on a spring (`paneSpring`, the share showing animated while a divider or the window sets its width at once), a segmented control's thumb glides to the segment picked (`selectionThumb`), another chat fades in, the inspector's profile and tab fade in from a little lower, the chat's pill eases to its new width, a message made under a second ago rises in (`riseIn`), and an unread dot pops. With Reduce Motion the fades stay and the sinking and sliding happen at once. The inspector's header holds its close button alone. A sheet (`overlay.go`) is the key window: it dims the window behind it and takes its clicks and keys, Escape cancels it and Return presses its default button; its panel sits in the middle of the window, and a press outside the panel cancels it as Escape does, except an alert's, which only its buttons answer (`pressedBackdrop` in `overlay.go`), and closing one hands the keyboard back to what had it. The composer has no Dictate button and General no Dictation section: Windows and Linux give the app no speech recognizer it uses.
- **Outputs** (`outputs.go`, `model/outputs.go`) and the file viewer (`viewer.go`, `picture.go`): the inspector's Outputs section, a file output or a file in a chat opened over the whole window, and a picture to pinch and slide: [The desktop viewer](outputs.md#the-desktop-viewer).
- **Limits** (`desktop/model/budgets.go`, `sheet_budget.go`, `sheet_connector_limits.go`): the snapshot's `budgets` and `budgets.changed` fill the store. The DM inspector's Limits row, the routine sheet's, and the plugin sheet's Call limit row are `disclosureRow`s that open the Limits and Call Limit sheets. The Limits sheet's fields are its own until it closes; its calls go out in order (the limits, then Resume) on the ordered main-thread queue, and a reply for a closed sheet is dropped: [Budgets and connector limits](budgets.md#in-the-apps).
Routines (`sheet_routine.go`, `model/routine_health.go`) and the Devices pane's Background service row follow the same rules; see [Routines](routines.md#the-apps). So do channels (`sheet_channel.go`, `channelRow`): [Channels](channels.md#in-the-apps).

A bot’s DM Profile card has the Access row (`disclosureRow`), which opens the same [Access sheet](bot-permissions.md#requests-to-the-user) (`sheet_access.go`): the plugins with their levels and tool checkboxes, then Files and Shell commands under the Runner's name. The sheet keeps the choices across frames and keys each plugin's row by its id; the tools the Runner sends arrive on the main-thread queue and keep what the user already chose, and a dismissed sheet ignores them. An access request in the chat offers Edit Access… and Dismiss, and the Plugins section reads No access for a plugin the bot may not use.
- **Workflow feedback** ([subject](feedback.md#in-the-apps)): Give Feedback… on a bot's message, the inspector's Feedback section, and the feedback, suggestion, and change sheets (`sheet_feedback.go`), over typed models and calls in `model/feedback.go`. The inspector keeps each bot's last `feedback.list` with its memory, and the sheets read it, so a `feedback.changed` refreshes them all; a closed sheet drops a late reply.
- **Title bar**: each pane of the main window has a header over its own background: the sidebar's holds the sidebar button and, at its end, round Search (the command palette) and Create buttons; the content's the title and subtitle, back and forward, and the Device picker in Settings, and for a chat its pill, running tasks, and Attention; and the inspector's its close button. A chat's transcript runs under the content's header, which always fades it out (`headerFade`: MyGo's `glass.Blur` under a mask and the content's color, strongest at the window's edge and gone just past the header). The chat's pill floats in the middle of the content over the fade, a capsule with the chat's avatars and name (a group's subtitle too); a click opens the inspector, or closes it. The main window shows no system material: the sidebar, content, and inspector each paint their own token color on every platform. Each pane divider has its own key and uses captured pointer drag state to resize across the adjacent panes until release, when its width is saved in preferences. The sidebar stays between 232 and 340 DIPs and collapses when dragged well past its minimum; the inspector stays between 268 and 320 DIPs. The headers are the title bar: the main window hides its own (`TitleBarHidden`, 52 pixels tall like the headers), keeps the window controls over the headers, and the headers drag the window (`DragWindow`). On macOS the traffic lights sit in the sidebar's header (`TrafficLightPosition` at 19, 19). On Windows and Linux MyGo puts the controls in a top corner: on Windows minimize, maximize, and close at the right, drawn as Windows 11 draws them, on Windows 10 too, and on Linux GTK's own title buttons wherever the desktop's button layout puts them, or none. The rightmost header and the sidebar and Create buttons keep clear of them by the insets `c.TitleBar()` reports. Onboarding hides its title bar too: its page fills the window under the window controls, the close button alone on Windows since the window can neither minimize nor maximize, and its background drags the window. The small settings window keeps the system's title bar. A window's title, which the taskbar and Alt+Tab show, is its content's title (the chat's, the settings pane's, Settings in the small window) followed by ` - Lorca`, the app's name, which stands alone where there is no title of its own (`setTitle` in `window.go`). On Windows and Linux every window's menu bar stays out of sight until Alt or F10 takes the keyboard to it (MyGo's `AutoHideMenuBar`), and its shortcuts work all along; the main window has no room for a bar on Windows, so there Alt and F10 open its menus from the window's top-left corner.
- **Skills** (`model/playbooks.go`, `model/skills.go`, `sheet_playbooks.go`): the inspector's Skills section, listed from the bot's Runner as it shows, the skill sheet, and Save as Skill ([Skills](skills.md#app-and-api)). Export writes the skill's zip through MyGo's save dialog, away from the view, and posts a failure back to the main thread.
- **Templates** (`sheet_template_share.go`, `sheet_template_import.go`, `settings_sharedlinks.go`, `template_files.go`): File › Share as Template… and New Bot from Template… open the [template sheets](templates.md#in-the-apps), and Settings › Shared Links lists the account's links; `template_files.go` asks the system's Open and Save dialogs for a path, and the CLI reads and writes the file. `urlSchemes` in `mygo.config.ts` declares `lorca://` (`lorca-dev://` for Lorca Dev), which the installer registers on Windows, the desktop entry on Linux, and Info.plist on macOS; `OnOpenURL` takes such a link with the launch or from a second instance and keeps it until the account and CLI are up.
- **Questions** ([subject](questions.md#in-the-apps)): the transcript's question card (`ask_card.go`) with its options, Other, Submit, and Skip. A code block in a message has a header with its language and Copy, While the pointer is over a finished message, Reply and Copy float on a pill beside its bubble (`message_actions.go`), with Edit on the user's latest message and Regenerate on the bot's reply to it where that exchange can [run again](runtime.md#running-a-reply-again) (`model/rerun.go`); Edit takes the message into the composer, which says Editing your message, gives back its draft on Escape, takes no new files, and marks the message Edited once sent. The pill is laid out of the flow so nothing moves: at the bubble's trailing side for a bot and its leading side for the user, or straddling its top corner where there is no room beside it, at its bottom when its top is under the header, never past the composer, and always inside the transcript (`placeActions`). The pointer can cross from the bubble onto the pill, which stays until the pointer is on neither.
- **Secrets** ([subject](secrets.md#in-the-apps)): the transcript's secret card (`secretCard` in `cards.go`) and Settings › Secrets with its sheet (`settings_secrets.go`).
- **The island** (`island.go`, `island_darwin.go`): a window at the top of every display says what the bots are doing when the main window is out of sight, following OpenBot's Dynamic Island (`packages/ui/src/features/dynamic-island`). Its states, most urgent first: a question waiting for the user, a result from the last eight seconds, a bot or coding agent at work, else idle. Each display gets a transparent 614×380 canvas on its top edge, so a panel opens inside it instead of resizing the window; the block itself is a 268×32 capsule (136 wide while idle, radius 16) that grows 32×8 under the pointer, and a 420-wide, 24-radius panel with a 14/20/20 inset while something waits. A state change morphs the block over 420 ms and the new content fades in from a little lower (MyGo's `AnimateTo` and `Transition`), option rows arrive in a stagger, and a row or button fades its fill over 120 ms and presses at 98% (`AnimateColor`, `AnimatePose`). The capsule is the app's mark and an unread count when idle, an avatar, the agent's name, and a Working chip at work; a result is the avatar, the bot's name, and the last line it said, and a click opens its chat. The panel leads with the bot's avatar, name, and a chip for what it needs (asks, needs approval, needs you), then the question or, for a permission, the command behind a warning bar; a bot's `ask_user` options are numbered rows answered in place (`Store.AnswerAsk`), a coding agent's permission puts the same decisions as its card in the last row with Allow once in ink (`Store.AnswerPermission`), a form the island cannot fill opens the chat, and the row counts the requests behind this one. The pointer turns clicks on and off: a 120 ms poll reads `Screen.CursorScreenPoint`, grows the capsule when the pointer is over the block, and calls `SetIgnoreMouseEvents` so a click outside it reaches the app below (MyGo 0.4.5 cannot forward moves to an ignored window, so the island polls). Under the pointer a working capsule opens into one 44-tall row per agent or bot at work, its chat named under it, and a click on a row opens that chat. A click on the capsule opens Lorca, or the chat of the question the header names, and View › Island (⌘⇧I, registered with `GlobalShortcut` so it works from another app too) opens the first waiting question, or Lorca when none waits. On macOS MyGo's window stops at the floating level under the menu bar, so `island_darwin.go` raises it with objc to `NSStatusWindowLevel`, drops its title bar, keeps it through a Space switch and a full-screen app, and swaps its class to `NSPanel` with the nonactivating style, so a click answers without taking the keyboard from what the user is typing in; the other platforms build the same code without the window. `Screen.OnDisplaysChanged` rebuilds a display's window. General › Island holds its settings, all on to start with: the island itself (`ShowsIsland`), one on every display or the main one alone (`IslandAllDisplays`), the idle capsule (`IslandIdleVisible`), growth under the pointer (`IslandHoverGrow`), the compact width as Small, Regular, or Large (`IslandSize`), and how long a result stays (`IslandResultSeconds`, 8 by default). The section is not shown off macOS.
- **Commands** (`commands.go`): one table gives the menu bar (File, Edit, View, Chat, Window, Debug, Help; on a Mac the app menu before them holds About, Check for Updates, Settings, Services, Hide, and Quit, which sit in File and Help on Windows and Linux; About is AppKit's standard about panel on a Mac and an alert with the version elsewhere) and the command palette's titles and enabled states, and the menu bars follow the table's states as the windows redraw. Ctrl stands where macOS has ⌘; Ctrl+1 to Ctrl+9 are the main window's own shortcuts, since the Windows menu bar keeps no hidden items. While a sheet is up only the app's own commands (Quit, About, Help, Check for Updates) run, as a sheet takes a Mac window's commands.

## Shared project context

A group's inspector has the Project section, and a row opens the same entry sheet (`project.go`): the entries a row each, a + menu that adds one, Check Now under a link, Open for a file, and a conflict alert when another Device saved first. `model/project_context.go` makes the `projects.*` calls; their replies come back on the store's main-thread queue, a sheet closed meanwhile ignores them, and `projects.changed` lists the group again. [Shared project context](project-context.md#the-apps) describes both apps.

## Workflows

The last onboarding page has Choose a Workflow… under Open Lorca, and the marketplace lists Workflows first; a workflow's page is among the marketplace pages in `desktop/workflows.go` over `desktop/model/workflows.go`: [Workflow onboarding](workflows.md#the-apps).
